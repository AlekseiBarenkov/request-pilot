# RequestPilot

Демонстрационное веб-приложение для подготовки заявок по обращениям клиентов
сервисной компании, которая ремонтирует бытовую технику. Сотрудник вставляет
обращение или выбирает пример, запускает разбор, проверяет извлечённые данные и
черновик ответа, а затем подтверждает результат. Приложение не отправляет
сообщения клиентам и не создаёт записи во внешней CRM.

Сейчас завершён **этап 1**: каркас приложения, общие контракты, демонстрационный
режим, каркас интерфейса и локальное хранилище. Редактор результата, сохранение из
интерфейса и подключение DeepSeek - следующие этапы.

## Что уже работает

- Запуск без API-ключа: сервер сам включает демонстрационный режим.
- Восемь подготовленных обращений с вымышленными данными.
- `POST /api/analyze`: демо-провайдер возвращает готовый разбор, сервер проверяет
  его Zod-схемой и подтверждающие цитаты.
- `GET /api/config`: режим, провайдер, модель и лимит текста.
- Главный экран: выбор примера, разбор, отмена запроса, просмотр полей и цитат.
- История в IndexedDB: список, счётчик, просмотр сохранённого разбора, сброс.
- Понятные ошибки API: пустой текст, слишком длинный текст, чужой текст в
  демо-режиме, невалидный ответ модели.
- Фейковый провайдер для будущих тестов с детерминированными ответами и
  маркерами ошибок.

## Стек

React 18, TypeScript strict, Vite, React Router, Ant Design, React Hook Form,
Zod, dayjs, Fastify, IndexedDB, tsup.

## Запуск

Требуется Node.js 20.19+ и npm.

```bash
npm install
npm run dev
```

- Приложение: http://localhost:5173
- API: http://127.0.0.1:3001
- Vite проксирует `/api` на Fastify.

`npm install` устанавливает зависимости.

### Режимы

Без переменных окружения и без ключа приложение запускается в демо-режиме:

```text
AI_PROVIDER=auto, ключа нет -> demo
```

В демо-режиме можно разобрать только один из восьми примеров. Если изменить текст,
сервер вернёт `DEMO_EXAMPLE_REQUIRED` и объяснит, что доступны только примеры.
Неверный ключ не переключает приложение в демо-режим.

Для проверки будущих тестов доступен `AI_PROVIDER=fake`. Этот провайдер
детерминированно отвечает на любой текст и запрещён в production.

Основные переменные текущего этапа:

| Переменная    | По умолчанию  | Назначение                            |
| ------------- | ------------- | ------------------------------------- |
| `PORT`        | `3001`        | порт Fastify                          |
| `AI_PROVIDER` | `auto`        | `auto`, `demo` или `fake`             |
| `NODE_ENV`    | `development` | `production` запрещает fake-провайдер |

Полный набор переменных, включая настройки DeepSeek, появится вместе с реальным
провайдером на этапе 4. Ключ хранится только на сервере и не попадает в браузер.

## Скрипты

| Команда                | Что делает                                        |
| ---------------------- | ------------------------------------------------- |
| `npm run dev`          | запускает Fastify и Vite одновременно             |
| `npm run dev:server`   | запускает только Fastify с `tsx watch`            |
| `npm run dev:web`      | запускает только Vite                             |
| `npm run build`        | проверяет типы, собирает `dist/` и `dist-server/` |
| `npm start`            | запускает production-сервер из `dist-server/`     |
| `npm run typecheck`    | проверяет типы фронтенда и сервера                |
| `npm run lint`         | запускает ESLint                                  |
| `npm run format`       | форматирует файлы Prettier                        |
| `npm run format:check` | проверяет форматирование                          |

Перед `npm start` выполните `npm run build`. Сервер отдаёт собранный `dist/` и
для клиентских маршрутов возвращает `index.html`, поэтому прямые ссылки вида
`/history/<id>` работают.

## Структура

```text
src/       интерфейс, страницы, фичи, тема, IndexedDB
server/    Fastify, маршруты, провайдеры, финализация
shared/    константы, Zod-схемы и восемь примеров
```

Направление зависимостей: `shared` не импортирует `src` и `server`; `src` и
`server` используют только `shared`. Сервер не импортирует код интерфейса.

## Проверки этапа

```bash
npm run typecheck
npm run lint
npm run format:check
npm run build
```

Проверено вручную:

- запуск без ключа и разбор всех восьми примеров через API;
- пустой текст, не строка, лишние поля, битый JSON, текст длиннее 8000 символов и
  тело больше 64 КБ дают ожидаемые коды ошибок;
- демо-пример разбирается в браузере, подтверждающие цитаты отмечены, результат
  получает фокус;
- история читает запись из IndexedDB и открывает сохранённый разбор;
- production-сервер отдаёт приложение, статику и SPA-fallback;
- проверка вёрстки на 1440 px и 390 px без горизонтальной прокрутки.

## Ограничения

- Подтверждение и сохранение из интерфейса появятся на этапе 2. Слой IndexedDB и
  страницы истории уже готовы.
- Адаптер DeepSeek подключается на этапе 4. До этого при `AI_PROVIDER=deepseek`
  или наличии ключа сервер сообщает, что провайдер ещё не подключён.
- Лимиты запросов и суточный предел реализуются на этапе 5.
- История хранится только в текущем браузере. Между вкладками синхронизации нет.
- Демонстрационные данные вымышлены. Не используйте реальные персональные данные
  в публичном демо.
