# RequestPilot

Демонстрационное веб-приложение для подготовки заявок по обращениям клиентов
сервисной компании, которая ремонтирует бытовую технику. Сотрудник вставляет
обращение или выбирает пример, запускает разбор, проверяет извлечённые данные и
черновик ответа, а затем подтверждает результат. Приложение не отправляет
сообщения клиентам и не создаёт записи во внешней CRM.

Сейчас завершены **этапы 1-7**: каркас, демо-режим, основной экран, история,
DeepSeek, лимиты, мобильная доступность и Playwright-тесты. Приложение готово к
локальному запуску и production-сборке.

## Что уже работает

- Запуск без API-ключа: сервер сам включает демонстрационный режим.
- Восемь подготовленных обращений с вымышленными данными.
- `POST /api/analyze`: демо-провайдер возвращает готовый разбор, сервер проверяет
  его Zod-схемой и подтверждающие цитаты.
- `GET /api/config`: режим, провайдер, модель и лимит текста.
- DeepSeek: OpenAI-совместимый адаптер, JSON-режим, системный промт с правилами
  компании, отключённый thinking, тайм-аут 45 секунд, отмена запроса и отсутствие
  автоматических повторов.
- Понятные ошибки DeepSeek: неверный ключ, закончившийся баланс, недоступность,
  тайм-аут, пустой или невалидный ответ. Ключ остаётся только на сервере.
- Лимиты live-режима: 5 запросов в минуту с IP, 3 одновременных запроса и 100
  реальных запросов в сутки. Для 429 отдаётся `Retry-After`; демо и fake лимиты
  не расходуют.
- Журнал содержит маршрут, режим, модель, длину текста, длительность, код ошибки
  и токены, но не тексты обращений и не ключи.
- Главный экран: выбор примера, разбор, отмена запроса, редактирование полей,
  списки недостающих сведений и вопросов, черновик ответа.
- Рабочий стол: шапка и футер закреплены, колонки обработки и карточки прокручиваются
  независимо. На мобильном остаётся одна общая прокрутка.
- Мобильная версия от 360 px: одна колонка, отсутствие горизонтальной прокрутки,
  цели нажатия от 44 px. После разбора страница прокручивается к результату, пока
  он ниже видна кнопка «К результату», кнопка сохранения закреплена внизу.
  Селекты на телефоне открываются нижней шторкой почти на весь экран.
  Предупреждающие модальные окна на телефоне полноэкранные, с кнопками внизу.
- Доступность: видимые подписи, `aria-describedby` и `role="alert"` у ошибок,
  фокус на заголовке результата и сохранённой записи, клавиатурная навигация,
  контраст не ниже 4.5:1, модальные окна Ant Design с удержанием фокуса и Esc,
  поддержка `prefers-reduced-motion`.
- Подтверждение и сохранение: запись в IndexedDB, переход к сохранённому разбору,
  защита от дублей и лимит 100 записей.
- Защита несохранённых изменений: подтверждение при уходе, выборе другого примера,
  повторном разборе и закрытии вкладки.
- Устаревший результат: баннер и блокировка сохранения до нового разбора.
- История: поиск по имени, телефону, содержанию и тексту, фильтр по категории,
  удаление, очистка, счётчик и пустые состояния. Заголовок и фильтры закреплены,
  прокручивается только список карточек, без сдвига контента при появлении скролла.
- При возврате фокуса история перечитывается. Повреждённое хранилище показывает
  восстановление со сбросом, в том числе при сохранении.
- Сохранённый разбор: отметки изменённых полей, копирование ответа и экспорт JSON.
- Понятные ошибки API и сохранения.
- Фейковый провайдер для тестов с детерминированными ответами и маркерами ошибок.

В dev-режиме кнопка «Заполнить демо-данными» появляется в пустой истории, а
кнопка «Добавить демо-данные» - в панели истории, если подготовленных записей
не хватает. Они создают 11 тестовых записей в IndexedDB для проверки поиска,
фильтров и действий.

## Стек

React 18, TypeScript strict, Vite, React Router, Ant Design, React Hook Form,
Zod, dayjs, Fastify, Helmet, OpenAI SDK, IndexedDB, Playwright, tsup.

## Запуск

Требуется Node.js 20.19+ и npm.

```bash
npm install
npm run dev
```

- Приложение: http://localhost:5173
- API: http://127.0.0.1:3001
- Vite проксирует `/api` на Fastify.

`npm install` устанавливает зависимости.

### Режимы

Без переменных окружения и без ключа приложение запускается в демо-режиме:

```text
AI_PROVIDER=auto, ключа нет -> demo
AI_PROVIDER=auto, ключ есть -> deepseek
```

В демо-режиме можно разобрать только один из восьми примеров. Если изменить текст,
сервер вернёт `DEMO_EXAMPLE_REQUIRED` и объяснит, что доступны только примеры.
Неверный ключ не переключает приложение в демо-режим: сервер вернёт
`PROVIDER_AUTH`, чтобы демо не приняли за реальный разбор.

Для проверки тестов доступен `AI_PROVIDER=fake`. Этот провайдер
детерминированно отвечает на любой текст и запрещён в production.

Полный набор переменных:

| Переменная                   | По умолчанию               | Назначение                            |
| ---------------------------- | -------------------------- | ------------------------------------- |
| `NODE_ENV`                   | `development`              | `production` запрещает fake-провайдер |
| `PORT`                       | `3001`                     | порт Fastify                          |
| `AI_PROVIDER`                | `auto`                     | `auto`, `deepseek`, `demo` или `fake` |
| `DEEPSEEK_API_KEY`           | -                          | ключ DeepSeek, только сервер          |
| `DEEPSEEK_BASE_URL`          | `https://api.deepseek.com` | OpenAI-совместимый endpoint           |
| `DEEPSEEK_MODEL`             | `deepseek-flash`           | имя модели                            |
| `AI_REQUEST_TIMEOUT_MS`      | `45000`                    | тайм-аут запроса к модели             |
| `AI_MAX_OUTPUT_TOKENS`       | `2000`                     | предел ответа модели                  |
| `AI_DAILY_REQUEST_LIMIT`     | `100`                      | реальных запросов в сутки, UTC        |
| `RATE_LIMIT_PER_MINUTE`      | `5`                        | запросов с одного IP в минуту         |
| `MAX_CONCURRENT_AI_REQUESTS` | `3`                        | одновременных запросов к модели       |
| `TRUST_PROXY`                | `0`                        | доверять `X-Forwarded-For`            |

Ключ хранится только на сервере, не попадает в клиентский бандл, ответы API и
логи. `.env` исключён из git, `.env.example` можно копировать.

Лимиты хранятся в памяти процесса: они сбрасываются при перезапуске и не
разделяются между несколькими инстансами. Для публичного live-демо нужен внешний
лимитер или шлюз; без него публичное демо должно оставаться в демо-режиме.

### Подключение DeepSeek

```powershell
Copy-Item .env.example .env
# откройте .env и заполните DEEPSEEK_API_KEY
npm run dev
```

Или задайте ключ в переменной окружения. После запуска проверьте режим в шапке:
должен быть бейдж «DeepSeek». Для ручного smoke-запуска примера 1:

```bash
npm run smoke:ai
```

Скрипт не печатает ключ и завершается с ошибкой, если DeepSeek не настроен.

## Скрипты

| Команда                | Что делает                                        |
| ---------------------- | ------------------------------------------------- |
| `npm run dev`          | запускает Fastify и Vite одновременно             |
| `npm run dev:server`   | запускает только Fastify с `tsx watch`            |
| `npm run dev:web`      | запускает только Vite                             |
| `npm run build`        | проверяет типы, собирает `dist/` и `dist-server/` |
| `npm start`            | запускает production-сервер из `dist-server/`     |
| `npm run typecheck`    | проверяет типы фронтенда и сервера                |
| `npm test`             | собирает проект и запускает 22 Playwright-теста   |
| `npm run smoke:ai`     | запускает live smoke-пример через DeepSeek        |
| `npm run lint`         | запускает ESLint                                  |
| `npm run format`       | форматирует файлы Prettier                        |
| `npm run format:check` | проверяет форматирование                          |

Перед `npm start` выполните `npm run build`. Сервер отдаёт собранный `dist/` и
для клиентских маршрутов возвращает `index.html`, поэтому прямые ссылки вида
`/history/<id>` работают.

## Структура

```text
src/          интерфейс, страницы, фичи, тема, IndexedDB
src/styles/   base, layout, components, forms, analysis, history, antd, modal, responsive
server/       Fastify, маршруты, провайдеры, промт, лимиты, финализация
server/providers/  demo, fake, deepseek
scripts/      smoke-ai.ts
tests/        API, demo и fake сценарии Playwright
shared/       константы, Zod-схемы и восемь примеров
```

Направление зависимостей: `shared` не импортирует `src` и `server`; `src` и
`server` используют только `shared`. Сервер не импортирует код интерфейса.

## Тесты

```bash
npm test
```

Команда сначала собирает frontend и server, затем запускает Playwright. Тесты
поднимают два Fastify-сервера с высокими лимитами:

- `AI_PROVIDER=demo` на `3111`;
- `AI_PROVIDER=fake` на `3112`.

Ключ DeepSeek не нужен, реальные запросы не выполняются. Каждый тест получает
новый контекст браузера и чистый IndexedDB. Проекты: desktop 1440x1000 и mobile
390x844, часовой пояс `Asia/Yekaterinburg`.

22 теста проверяют API, ошибки провайдера, отмену, demo-сценарий, сохранение и
историю, мобильную и десктопную вёрстку. Тесты используют установленный Chrome.
Если его нет:

```bash
npx playwright install chrome
```

Для ручной проверки реального API используйте `npm run smoke:ai`.

## Проверки этапа

```bash
npm run typecheck
npm run lint
npm run format:check
npm test
```

Проверено вручную:

- запуск без ключа и разбор всех восьми примеров через API;
- пустой текст, не строка, лишние поля, битый JSON, текст длиннее 8000 символов и
  тело больше 64 КБ дают ожидаемые коды ошибок;
- полный сценарий: пример -> разбор -> правка поля и списка -> подтверждение ->
  сохранение -> открытие записи -> перезагрузка истории;
- изменение поля очищает цитату, возврат значения модели возвращает подтверждение;
- устаревший результат блокирует сохранение, возврат исходного текста снимает
  блокировку;
- уход со страницы и повторный разбор требуют подтверждения при несохранённом
  результате;
- лимит истории показывает ошибку сохранения и сохраняет правки на экране;
- повторное сохранение записи не создаёт дубликат;
- поиск работает по имени, цифрам телефона, содержанию и тексту; фильтр по
  категории показывает нужные записи;
- удаление одной записи и очистка истории требуют подтверждения и обновляют счётчик;
- пустые состояния «нет разборов» и «ничего не найдено» различаются;
- копирование черновика и экспорт JSON с `modelAnalysis` и `analysis` работают;
- изменённые поля на странице записи помечены, цитата у них не показывается;
- DeepSeek-адаптер проверен на локальном mock-сервере: в запрос уходят
  `response_format`, `thinking: disabled`, `max_tokens`, `temperature` и `maxRetries: 0`;
- 401, 402, 429, 500, тайм-аут, пустой ответ, `finish_reason: length` и битый JSON
  дают ожидаемые коды ошибок;
- ключ не попадает в ответ API, клиентский бандл и тестовый вывод;
- лимит 2 запроса в минуту пропускает два запроса, третий получает 429 с
  `Retry-After`, а провайдер вызывается только дважды;
- лимит одновременных запросов возвращает `SERVER_BUSY` и освобождается после
  завершения запроса;
- суточный лимит срабатывает и сбрасывается на следующие сутки UTC;
- при возврате фокуса история перечитывается, а сохранённый разбор не требует
  повторного обращения к модели;
- production-сервер отдаёт приложение, статику и SPA-fallback, а Helmet добавляет
  защитные заголовки;
- мобильный сценарий на 360 px: одна колонка, нет горизонтальной прокрутки,
  цели нажатия 44 px, автоматический переход к результату, кнопка «К результату»
  и закреплённое сохранение;
- фокус после разбора переходит на заголовок результата, после сохранения - на
  заголовок записи; ошибки связаны с полями через `aria-describedby`;
- контраст основных пар текст/фон проверен, минимальное значение выше 4.5:1;
- 22 Playwright-теста проходят в demo и fake режимах на desktop и mobile;
- проверка вёрстки на 1440 px и 390 px без горизонтальной прокрутки.

Live-проверка DeepSeek требует ключ в `.env`; в репозитории его нет.
`npm test` не делает реальных запросов и не расходует баланс.

## Ограничения

- Лимиты хранятся в памяти процесса: сбрасываются при перезапуске и не работают
  между несколькими инстансами. Для публичного live-демо нужен внешний лимитер
  или шлюз, иначе безопаснее оставить демо-режим.
- Для live-проверки DeepSeek нужен ключ в `.env`; без него доступны демо-режим,
  fake-провайдер и локальный mock.
- Playwright использует установленный Chrome. На CI установите его командой
  `npx playwright install chrome`.
- История хранится только в текущем браузере. Между вкладками синхронизации нет,
  история перечитывается при возврате фокуса.
- Кнопка «Заполнить демо-данными» доступна только в dev-режиме.
- Демонстрационные данные вымышлены. Не используйте реальные персональные данные
  в публичном демо.
